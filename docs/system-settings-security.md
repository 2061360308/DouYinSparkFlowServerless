# 系统凭据与调度排查

系统配置中的 `platform_access_key_id`、`platform_access_key_secret`、`image_registry_password` 写入 `system_secrets` 表，使用 AES-GCM 和固定 `SPARK_COOKIE_KEY_B64` 加密，每个键名参与认证。原 `system_config` 的对应值清空。业务代码通过 `SystemConfigDB` 读取；不要直接查询原表或直接写入敏感字段。

升级时先备份数据库和现有加密密钥，在同样环境变量下运行 `python -m core.db`，再启动 API。初始化会创建新表、迁移旧明文；API 启动也会检查遗漏的旧值。迁移事务失败不会清除旧值，可修复密钥后重试。不使用开发模式的随机密钥保存系统凭据。数据库旧备份、SQLite 历史页或 WAL 不会因此自动擦除，需要按部署环境的备份保留策略处理。

管理员 GET 接口始终返回空的敏感字段和 `secret_configured` 标记，不返回明文或密文。PUT 中敏感字段留空表示保留；非空表示替换；只有显式 `clear_secret_keys` 才清除，不能同一次请求替换并清除同一个键。密钥解密失败时管理页仍可读取并重新填写；安装记录使用同一环境密钥，但需要走安装流程恢复。

安装成功后，运行服务优先使用安装记录中的 AK/SK。系统设置中的平台 AK/SK 是备用配置，修改不会旋转安装凭据。修改普通配置不会更新已部署资源，也不会自动同步现有任务。不要通过手动修改地域或总线来迁移部署，旧调度资源需要另行清理。

任务同步失败时执行映射保持关闭，用户可在任务页重试同步。错误提示区分配置缺失、凭据解密失败、身份验证失败、权限不足、限流、连接异常与本机调度工具缺失；未知 SDK 错误采用通用提示，不将原始报文、URL 或密钥写入用户可见错误。超时可能表示远程操作已经完成，重试使用已有事件源名称进行更新。

调度远程调用已移出数据库事务，并新增持久化队列、租约恢复和退避重试；需要部署持续唤醒入口才会自动运行，详见 [调度队列](schedule-queue.md)。

验证：隔离数据库的安装/API 场景包含旧凭据迁移、重复迁移、字段脱敏、空值保留、显式清除、错误密钥拒绝，以及真实 API 路由上的调度权限失败与重试；浏览器冒烟使用模拟 API，不访问真实云服务。
