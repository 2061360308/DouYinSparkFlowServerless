# 执行协议 v3：一次计划只尝试一次

## 本次范围

修正处理器返回 `ok: false` 仍被标记成功的问题，为续火任务增加持久化执行权，并区分页面提交证据与真正送达。通用非续火处理器保留原接口与返回兼容性，不宣称具备这套防重复保障。

## 状态与归属

业务任务决定发送时间、账号、好友和消息。现有 `TaskRun` 的 `(task, scheduled_for)` 唯一约束决定一次计划是否已经领取；新增 `execution_claims` 保存对应执行令牌的哈希。执行器仅经内部 API 读写，不连接数据库。

1. `POST /api/internal/scheduled-tasks/{id}/claim` 在事务中检查任务和调度状态，并创建唯一执行记录。并发请求只有一个获得令牌，其余直接跳过。领取响应丢失时也不发送，后续请求不会重新领取。
2. 执行器打开页面并准备消息，在按回车之前调用 `POST /api/internal/executions/{run_id}/sending`。服务端核对令牌、执行窗口、启停状态、账号和消息快照，再将记录从 preparing 改为 sending。这个授权只允许成功一次；响应丢失时不能再次发起发送。
3. `POST /api/internal/executions/{run_id}/finish` 更新同一条记录。发送前失败记 failed；已经进入 sending 后失败或连接中断，保守记 uncertain。终态不能由重复回写改成成功。

这提供的是同一计划的“至多一次尝试”，不是“保证送达且绝不重复”。无法同时承诺外部页面动作与本地数据库原子提交，因此明确优先避免重复发送；代价是某些实际上未发送的请求也需要人工核实，不能自动重发。

## 计划时间与超时

云函数 HTTP 事件必须带 CloudEvent 原始 `time`，重投时沿用原时间。服务端归一到 UTC 分钟，核对当前任务的上海时间，并只接纳计划时间后 10 分钟内的事件。旧计划、更改前的时间、未来时间和过期事件均不执行。CLI 可传 `--scheduled-for`；未传时由服务端推导最近一次计划，仅允许同样的 10 分钟窗口。

执行开始后超过 10 分钟不再授予发送权。读取执行记录列表时，会把已超时的 preparing 标记为失败，sending 标记为待核实；此操作不重新授予令牌，也不会补发。已经结束的较新计划不会被迟到的旧结果覆盖摘要。

旧版本以实际执行时刻保存的记录若落在该计划的执行窗口内，也会阻止重复领取，避免升级后重做已有尝试。不要删除执行记录来绕过防重复约束。

## 页面确认的证据边界

发送前记下编辑框和会话列表外、与完整消息文本相符的可见内容数量；发送后同时检查编辑框清空及匹配内容新增。旧的同文消息不能单独作为新发送成功的证据。好友选择必须匹配唯一稳定 ID，而非昵称；发送前复核聊天区域的资料链接，缺失、冲突或切换均停止。

- **页面已显示（submitted）**：页面出现新增内容；不代表服务端确认送达或对方已读。
- **待核实（uncertain）**：已进入发送阶段，但页面确认超时、执行器异常或结果未回传；检查聊天记录，系统不会自动重发。
- **失败（failed）**：未进入发送阶段即失败。

本版本不把普通页面回显写成 success。`execution_evidence` 保存领取时的账号和好友 ID 快照及后续回执；`POST /api/internal/executions/{id}/receipt` 是受服务令牌和执行令牌保护的可信适配器入口。规范化回执必须包含来源、消息摘要、好友 ID、服务端消息 ID、会话 ID、带时区的观察时间和 accepted/delivered/read 级别。同一服务端消息不能归属两个执行，证据只升级、不降级。普通 finish 不能绕过证据将执行标为 success。

**目前没有接入经过验证的抖音回执解析器。** `douyin_verified_adapter_v1` 是预留的可信适配器契约标识，不是对抖音接口格式的断言。当前页面执行器不调用此入口。不能直接把任意 HTTP 200、DOM 文字或未关联到本次消息的响应转换成此回执。测试使用规范化模拟证据验证服务端状态机，不能证明真实送达。接入前必须核验平台协议与账号、会话、消息关联，再实现解析器；此项仍未完成。

好友同步使用当前可见会话中的 `https://www.douyin.com/user/{sec_uid}` 资料链接，按 ID 合并缓存，不清空未显示的联系人。任务编辑页提供同步和选择入口。该 DOM 适配尚未实机验证；页面没有可判定的资料链接时会停止，不能声称已经兼容全部真实抖音页面。已有无 ID 的任务需重新选择联系人，不能依靠同名回退发送。

## 发布与兼容

1. 暂停调度并等待原执行器结束，备份数据库。
2. 对目标数据库运行 `python -m core.db`，新增 `execution_claims`、`execution_evidence`、`schedule_jobs` 等表；现有 TaskRun 字段不变。队列运行方式见 [调度队列](schedule-queue.md)。
3. 发布后端及前端，构建并发布包含新 `core/api_client.py`、`core/task/run.py`、处理器及 invoke_server 的任务执行器镜像。
4. 新执行器发送 `X-Spark-Execution-Protocol: 3`。后端拒绝旧版本（包括 v2）读取续火任务，避免旧昵称匹配逻辑继续发送；旧的续火 started/result 回写返回 409，旧 `/spark-tasks/{id}/runs` 写入返回 410。
5. 核对 EventBridge 投递仍保留原始 CloudEvent time，再恢复调度并进行受控联调。仅更新控制台不会自动更新已部署的执行器镜像。

回滚时不要清除执行记录或重新启用旧执行器补跑旧事件；先暂停任务并核实发送阶段记录。尚未验证生产 PostgreSQL 并发及真实云端投递。

## 验证

`python -m unittest discover -s tests -v` 包含处理器失败传播、重复领取、领取响应丢失、结果回写失败、真实临时 SQLite 的并发请求、发送令牌、暂停检查、快照不匹配、终态保护与超时用例。

`python tests/message_confirmation_smoke.py` 使用本机 Edge 和合成聊天 DOM，拦截所有页面请求，验证旧消息拒绝、页面新增、发送权拒绝、同名不同 ID、改名、聊天对象切换、缺失 ID 和可见联系人扫描。它不会访问真实抖音账号。

`python tests/ui_scheduling_smoke.py` 在本地 Vite 5175 端口用隔离 API 数据检查执行记录的新状态。前端另运行 `npm test` 和 `npm run build`。
